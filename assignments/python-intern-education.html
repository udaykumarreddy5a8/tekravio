// The Problem
EduTrack FastAPI uses SQLAlchemy 2.x async engine (create_async_engine) with AsyncSession. All routes are async def. Database relationships are loaded eagerly with selectinload() or joinedload() — never rely on lazy loading in async context. Pydantic v2 models use ConfigDict(from_attributes=True) for ORM compatibility. Type hints on every function, mypy --strict must pass.

01
Course & Content Management
// 20 marks
▼

SQLAlchemy models with relationships and Pydantic v2 schemas.

course/schemas.pyPydantic v2
from pydantic import BaseModel, Field, ConfigDict
from decimal import Decimal
from .enums import Category, Difficulty

class CourseCreate(BaseModel):
    title: str = Field(min_length=5, max_length=100)
    category: Category
    difficulty: Difficulty
    price: Decimal = Field(ge=Decimal('0'), decimal_places=2)

class CourseResponse(CourseCreate):
    model_config = ConfigDict(from_attributes=True)
    id: UUID
    published: bool
    created_at: datetime
    modules: list['ModuleResponse'] = []
SQLAlchemy models: Define Course, CourseModule, Lesson using DeclarativeBase. Use Mapped[str] type annotations (SQLAlchemy 2.x style). Relationship: modules: Mapped[list['CourseModule']] = relationship(order_by='CourseModule.module_order').
Pydantic v2 schemas: class CourseCreate(BaseModel): title: str = Field(min_length=5, max_length=100); category: CourseCategory; price: Decimal = Field(ge=0, le=Decimal('99999.99')). Use model_config = ConfigDict(from_attributes=True) on response schemas. Create a CourseResponse that includes modules.
FastAPI dependency: Create async def get_db() -> AsyncGenerator[AsyncSession, None] as a FastAPI dependency. Use with Depends(get_db) in route functions. The session is committed on success and rolled back on exception via a try/finally in the generator.
Publish validation: async def publish_course(course_id: UUID, db: AsyncSession, current_user: User) -> CourseResponse. Use SQLAlchemy's select(func.count()).where() to count lessons. If zero, raise HTTPException(status_code=422, detail='Course needs at least one lesson').
02
Enrollment & Progress
// 22 marks
▼

FastAPI dependencies for enrollment guards and async SQLAlchemy queries.

Enrollment dependency: Create a FastAPI dependency: async def require_enrollment(course_id: UUID, db: AsyncSession, user: User = Depends(get_current_user)) -> Enrollment. This dependency fetches the enrollment and raises 404 if not found. Use in lesson progress routes.
Async queries: All database operations use await db.execute(select(Model).where(...)). Fetch the scalar: result = await db.scalar(select(Enrollment).where(...)). Never use synchronous ORM calls in async routes.
Progress calculation: Use SQLAlchemy aggregate: await db.scalar(select(func.count()).select_from(Lesson).join(CourseModule).where(CourseModule.course_id == course_id)). Do both counts (total + completed) in a single asyncio.gather call.
Completion status: Return a Pydantic model: class CompletionStatus(BaseModel): lessons_complete: bool; quizzes_passed: bool; eligible: bool; certificate_code: Optional[UUID] = None. Use Python's decimal module if any percentage calculation is needed.
03
Quiz System
// 22 marks
▼

Quiz submission with Python's typing and Pydantic model validation.

Answer schemas: class AnswerItem(BaseModel): question_id: UUID; selected_option_id: UUID. class QuizSubmitRequest(BaseModel): answers: list[AnswerItem] = Field(min_length=1). Pydantic v2 validates the list is not empty.
Scoring function: A pure function (no DB, fully testable): def calculate_score(answers: list[AnswerItem], questions: list[QuestionWithOptions]) -> tuple[int, int] returns (correct_count, total_count). Testable with pytest without any mocking.
Attempt validation: Use Python exceptions: class QuizAlreadyPassedError(Exception): pass. In the service: if any(a.status == 'PASSED' for a in existing_attempts): raise QuizAlreadyPassedError(). The route handler catches domain exceptions and maps to HTTP codes.
Exception handler: Register with FastAPI: @app.exception_handler(QuizAlreadyPassedError) async def quiz_passed_handler(request, exc): return JSONResponse(status_code=409, content={'detail': 'Quiz already passed'}).

Search & Dashboards

Dynamic SQLAlchemy where clauses and async parallel queries.

Dynamic query builder: Build the WHERE clause in Python: stmt = select(Course).where(Course.published == True). Then conditionally: if category: stmt = stmt.where(Course.category == category). Use SQLAlchemy's .where() chaining pattern.
Parallel async queries: Use asyncio.gather for independent queries: total_lessons, completed_lessons = await asyncio.gather(count_total_lessons(course_id, db), count_completed_lessons(user_id, course_id, db)).
Pagination utility: class PaginatedResponse(BaseModel, Generic[T]): data: list[T]; total: int; page: int; size: int; total_pages: int. Generic Pydantic model. Use: PaginatedResponse[CourseResponse].
Instructor dashboard: Use SQLAlchemy subqueries for completion rate: a correlated subquery that counts students with all lessons done divided by total enrolled. Document the SQL it generates with print(stmt.compile()).

// 02 · Design Questions
Answer in README.md

Python/FastAPI-specific patterns.

Q1
FastAPI's dependency injection uses Python generators for the database session. The yield in get_db() separates setup (before yield) from teardown (after yield). What happens to the session if a route handler raises an HTTPException? Is the session properly closed?
Q2
SQLAlchemy 2.x async sessions require await on all operations. But SQLAlchemy's lazy-loading of relationships is not compatible with async sessions. How do you load a Course with its modules relationship using async SQLAlchemy?
Q3
Pydantic v2's model_validator runs after field validation. Where would you use it in the EduTrack schemas? Give one example where cross-field validation is needed.
Q4
The calculate_score function is a pure function. Why is this design choice specifically good for testing? What would need to be different if the scoring logic were inside the route handler?
