01
Prompt Engineering Showcase
// 22 marks
▼

Design three production-ready prompts for Tekravio. These are not demo prompts — they must be clean enough to put into a prompt library and hand to a team member tomorrow.

Structured output example — Code Review PromptSystem Prompt
You are a senior software engineer at Tekravio.
When given code, you review it and respond ONLY as JSON.
Never add explanation outside the JSON block.

Response schema:
{
  "rating": number,        // 1-10
  "language": string,
  "bugs": [
    { "line": number, "issue": string, "fix": string }
  ],
  "security_issues": [string],
  "improvements": [string],
  "summary": string       // one sentence
}

Rules:
- If no bugs found, return empty array, not null
- Rating above 8 only if zero critical bugs
- security_issues only for actual vulnerabilities
Prompt 1 — Code Review: A system prompt that acts as a senior Java/Python code reviewer. Given a code snippet, it must: identify bugs, security issues, and code smells; rate the code 1–10 with justification; suggest specific line-level improvements; and output in a structured JSON format with fields: rating, bugs, security_issues, improvements, summary. Test it on a real snippet you write. Show the raw output.
Prompt 2 — Candidate Screening: A prompt that takes a job description + a resume text and outputs: fit score (0–100), top 3 strengths relative to the JD, top 3 gaps, a recommended interview question list (5 questions), and a one-line recruiter summary. The output must always be structured — no free-form paragraphs. Test with the AI Prompt Engineer JD from this assignment and a sample resume you create.
Prompt 3 — Meeting Summary: A prompt that converts raw meeting transcript text into: action items (owner + due date), key decisions made, open questions, and a 3-sentence executive summary. Test it on a realistic mock transcript you write (minimum 300 words of transcript). Output must be clean enough to paste into a Notion page.
Prompt iteration log: For ONE of the three prompts above, show a v1 → v2 iteration. Include: what v1 produced, what was wrong with it, exactly what you changed in the prompt and why, and what v2 produced. This is the most important part of Module 1 — showing you can debug prompts.
// Note

The most common prompt engineering mistake is not specifying the output format precisely enough. Show in your iteration log exactly how an imprecise output format caused a problem and how you fixed it.

03
AI Model Comparison
// 18 marks
▼

Pick one Tekravio use case and run the same prompt through four different AI models. Write an honest comparison and a model recommendation with business justification.

Cost calculation — templatePython
models = {
  "gpt-4o":          { "input": 2.50, "output": 10.00 },  # per 1M tokens
  "claude-sonnet-4-6": { "input": 3.00, "output": 15.00 },
  "gemini-1.5-pro":   { "input": 1.25, "output": 5.00  },
  "mistral-large-3":  { "input": 2.00, "output": 6.00  },
}

def monthly_cost(model, avg_input_tokens, avg_output_tokens, runs_per_month):
    p = models[model]
    return ((avg_input_tokens * p["input"] +
             avg_output_tokens * p["output"]) / 1_000_000) * runs_per_month

# Example: 500 email drafts / month, ~800 input + 400 output tokens
for model in models:
    cost = monthly_cost(model, 800, 400, 500)
    print(f"{model}: ${cost:.2f}/month")
Choose your use case: Pick one: (A) Writing personalised cold outreach emails from a lead's LinkedIn profile. (B) Reviewing a 200-line Python function for bugs and security issues. (C) Answering a technical HR question from the Tekravio employee handbook. (D) Generating unit test cases for a Spring Boot REST endpoint.
The four models: Test at minimum four models. Suggested: GPT-4o or GPT-5.5, Claude Sonnet 4.6 or Fable 5, Gemini 1.5 Pro or Gemini 3.1 Pro, and one open-source model (Llama 4 Scout via Groq, Mistral Large 3, or Qwen 3 via OpenRouter). Use the exact same prompt on all four. Record the actual outputs.
Comparison matrix: Build a table comparing all four models across: output quality (subjective 1–10 with reasoning), accuracy / hallucination risk (did any make something up?), response time (seconds), estimated cost per 1,000 runs (calculate from API pricing × token count), context window (is it relevant for this use case?), and privacy considerations (is sending this data to this provider safe?).
Recommendation: Write a one-paragraph recommendation: which model would you use at Tekravio for this use case, and why? Include a fallback model if the primary is unavailable or too expensive. If cost is a deciding factor, show the math: e.g. 500 emails/month × average 800 tokens = X tokens = ₹Y/month.
// Note

This module is worth 18 marks but is often the most insightful for reviewers. Candidates who blindly recommend GPT-4 for everything fail this module. The right answer depends on the use case.

04
Mini RAG System or AI Agent
// 22 marks
▼

Build one working system. Either a RAG pipeline that answers questions from a document set, or a multi-step AI agent that completes a real task end-to-end. Real code, real output.

Option A — RAG pipeline skeletonPython
from langchain.document_loaders import DirectoryLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_anthropic import ChatAnthropic

# 1. Load docs
docs = DirectoryLoader("./tekravio_kb").load()

# 2. Chunk
chunks = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50
).split_documents(docs)

# 3. Embed + store
db = Chroma.from_documents(chunks, OpenAIEmbeddings())

# 4. Query
def ask(question: str) -> str:
    results = db.similarity_search(question, k=3)
    context = "

".join(r.page_content for r in results)
    return ChatAnthropic(model="claude-sonnet-4-6").invoke(
        f"Context:
{context}

Question: {question}

Cite your source."
    ).content
Option A — RAG System: Build a RAG system that answers questions from a small Tekravio knowledge base. Create 3–5 sample documents (job descriptions, an HR policy, a technical spec — you can write these yourself). Implement: document loading and chunking, embedding with any model (OpenAI, Cohere, or a local model), storage in a vector DB (Chroma, Pinecone free tier, FAISS, or Qdrant), retrieval with cosine similarity, and answer generation with source citation. Test with 5 questions and show the retrieved chunks alongside the answer.
Option B — AI Agent: Build a multi-step AI agent that completes a task using tool calling. Suggested task: given a GitHub username, (1) fetch their public repos via GitHub API, (2) analyse their top 3 repos using AI, (3) generate a candidate technical profile. OR: given a company name, (1) search for recent news, (2) extract key facts, (3) draft a personalised sales email. Use OpenAI function calling, Anthropic tool use, or LangChain with tools. Show at least 3 tool calls in the agent trace.
Code quality requirements: Regardless of Option A or B: all code must run with a single command (python main.py or node index.js). Include a requirements.txt or package.json. Add a .env.example file showing which API keys are needed. Handle the case where the API returns an error or no results. README must explain how to run it in under 5 minutes.
Test and document: Run your system with 5 test inputs. For each test: show the input, show the output, mark it as correct / partially correct / incorrect, and explain any incorrect outputs. If your system hallucinates or retrieves wrong chunks, explain why and what you would improve.
// Note

We do not care which option you pick. We care about: does it run, does it produce useful output, and can you explain what it does and where it fails? A working simple system beats a broken complex one every time.

05
AI Governance & Prompt Security
// 16 marks
▼

Write the documents that would govern AI usage at Tekravio. This is not a box-ticking exercise. These documents will protect real company and client data.

Tekravio AI Usage Policy: Write a one-page (500–800 word) AI Usage Policy for Tekravio covering: (a) which AI tools are approved and for what use cases, (b) what information must NEVER be entered into any AI tool (client source code, employee data, contracts, financial data), (c) what to do before using a new AI tool not on the approved list, (d) who owns the output of AI-generated work, (e) how to handle AI errors or hallucinations in a client deliverable. Make it practical — something a developer or HR team member would actually read and follow.
Prompt injection risk assessment: Explain prompt injection: what it is, why it matters in a business context, and give two realistic examples of how it could harm Tekravio (e.g. a support chatbot being manipulated to reveal internal data). For each example: describe the attack, describe the prompt-level defence you would add (not application-level security — prompt-level), and show the before/after prompt.
Hallucination prevention checklist: Create a 10-point checklist that a Tekravio team member runs before trusting any AI output for a client-facing deliverable. For each point: state the check and explain why it matters. Example format: [ ] Verify all names, numbers, and dates cited by the AI against original sources — AI frequently fabricates statistics.
Automation safety rules: Define 5 safety rules for any automated workflow that runs without human supervision at Tekravio. Address: maximum actions per run, what triggers a human approval checkpoint, how sensitive data is handled in transit between tools, what the fallback is if an API fails, and how you log what the automation did for audit purposes.
// Note

A company that uses AI without governance documents is one incident away from a serious client or legal problem. This module tests whether you have the maturity to build AI systems responsibly — not just technically.

// 02 · Design Questions
Answer in README.md

These come up on day one. We discuss them in the review call — short written answers, honest thinking.

Q1
A developer at Tekravio asks you to build a GitHub Actions workflow that uses Claude to review every pull request and auto-approve it if the AI gives a score above 8/10. What are the risks of full auto-approval, and how would you redesign the workflow to keep a human in the loop without making it annoying?
Q2
Tekravio's HR team wants to use an AI prompt to screen 200 resumes and shortlist the top 20. The prompt was written by a developer and tested on 10 resumes. Two months later, the HR lead notices that shortlisted candidates are almost always from a specific set of universities. What likely happened at the prompt level, and how would you audit and fix it?
Q3
You built an n8n automation that reads emails, extracts tasks, and creates Jira tickets. One morning it creates 340 tickets from a single email thread. Walk through exactly what caused this and describe the specific safeguard you add to the automation to prevent it happening again.
Q4
A client asks Tekravio to build an internal AI assistant using their proprietary documentation. The client wants to use OpenAI's API. What data privacy questions do you ask the client before proceeding, and under what conditions would you recommend a self-hosted open-source model instead?
