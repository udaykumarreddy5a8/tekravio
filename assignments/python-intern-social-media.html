// The Problem
ConnectHub FastAPI uses asyncio.gather for parallel follower/following count queries. The feed query uses a correlated subquery to filter posts by followed users. Notification creation uses FastAPI's built-in BackgroundTasks — notifications are created after the response is sent without blocking it. Follow status is a Python StrEnum stored as a native PostgreSQL ENUM.

User Profile & Auth
// 20 marks
▼

FastAPI JWT auth with role-based dependency injection.

JWT auth: Use python-jose[cryptography]. Create access token: jwt.encode({'sub': str(user.id), 'role': user.role}, SECRET_KEY, algorithm='HS256'). Dependency: async def get_current_user(token: str = Depends(oauth2_scheme), db: AsyncSession = Depends(get_db)) -> User.
Profile response type: Use Pydantic discriminated union: class PublicProfile(BaseModel): ...no_posts_count vs class PrivateLockedProfile(BaseModel): ...is_private_notice: str. Route returns Union[PublicProfile, PrivateLockedProfile] based on follow status.
Username validation: Pydantic: username: str = Field(min_length=3, max_length=30, pattern=r'^[a-zA-Z0-9_]+$'). The pattern ensures no spaces or special characters.
Search: Use PostgreSQL ilike: select(User).where(or_(User.username.ilike(f'%{q}%'), User.display_name.ilike(f'%{q}%'))).limit(20).
02
Follow System
// 22 marks
▼

Follow/unfollow with Python StrEnum and SQLAlchemy insert-on-conflict.

FollowStatus StrEnum: class FollowStatus(StrEnum): PENDING = 'PENDING'; APPROVED = 'APPROVED'; BLOCKED = 'BLOCKED'. SQLAlchemy: status: Mapped[FollowStatus] = mapped_column(Enum(FollowStatus)).
Follow service: async def follow_user(follower_id: UUID, target_username: str, db: AsyncSession) -> FollowResult. Fetch target user, check not self, get current FollowStatus, create follow with APPROVED (public) or PENDING (private). Typed return: FollowResult = Literal['followed', 'requested', 'already_following', 'self_follow_error'].
Upsert for follow: Use insert(Follow).values(...).on_conflict_do_nothing(index_elements=['follower_id','following_id']). Check if inserted: result.rowcount == 1. If 0: already exists, return 'already_following'.
Follower count: follower_count, following_count = await asyncio.gather(db.scalar(select(func.count()).where(Follow.following_id == user_id, Follow.status == 'APPROVED')), db.scalar(select(func.count()).where(Follow.follower_id == user_id, Follow.status == 'APPROVED'))).

Post visibility enforcement with SQLAlchemy where clause builder.

Visibility WHERE builder: def build_post_visibility(viewer_id: UUID) -> BinaryExpression: return or_(Post.visibility == 'PUBLIC', and_(Post.visibility == 'FOLLOWERS_ONLY', Post.author_id.in_(select(Follow.following_id).where(Follow.follower_id == viewer_id, Follow.status == 'APPROVED'))), Post.author_id == viewer_id).
Soft delete mixin: Create a SQLAlchemy mixin: class SoftDeleteMixin: deleted_at: Mapped[Optional[datetime]] = mapped_column(default=None). Override the query in a custom Query class or use an event listener.

Feed & Notifications
// 20 marks
▼

Cursor-based feed and notification factory.

Feed query: stmt = select(Post).where(Post.author_id.in_(select(Follow.following_id).where(Follow.follower_id == user_id, Follow.status == 'APPROVED')), Post.deleted_at == None, Post.visibility != 'PRIVATE').order_by(Post.created_at.desc()). Apply cursor: .where(Post.created_at < cursor_time).
Notification factory: Python dataclass: @dataclass class NotificationFactory: @staticmethod def new_follower(actor_id: UUID, recipient_id: UUID) -> dict: return {'type': 'NEW_FOLLOWER', 'actor_id': actor_id, 'recipient_id': recipient_id, 'message': 'started following you'}.
Background notification: @router.post('/follow/{username}') async def follow(username: str, background_tasks: BackgroundTasks, ...): result = await follow_service.follow(...); background_tasks.add_task(create_notification, NotificationFactory.new_follower(...), db); return result.
Unread count: GET /api/notifications/unread-count returns {'count': int}. Use await db.scalar(select(func.count()).where(Notification.recipient_id == user_id, Notification.is_read == False)).

Hashtag extraction and pytest visibility tests.

Hashtag parser: import re; def extract_hashtags(content: str) -> list[str]: return list({tag[1:].lower() for tag in re.findall(r'#[a-zA-Z][a-zA-Z0-9_]*', content)}). A set comprehension removes duplicates. Return as a list.

// 02 · Design Questions
Answer in README.md

Python/FastAPI-specific patterns.

Q1
FastAPI's BackgroundTasks.add_task() runs after the response is sent. But the task uses the same AsyncSession that was closed after the response. How do you ensure the background task has its own database session?
Q2
The feed query uses a subquery to get followed user IDs. SQLAlchemy generates a nested SELECT. As the user follows more people (500+ users), this subquery gets large. What index on the Follow table makes this efficient?
Q3
Python's StrEnum values compare equal to their string equivalents: FollowStatus.APPROVED == 'APPROVED' is True. This is convenient but can hide bugs. Give one example where this implicit equality could cause a subtle bug in your service code.
Q4
The build_post_visibility function returns a SQLAlchemy expression. Unit testing it by just checking the Python object structure (like checking it's an or_ expression) is insufficient. What database test would actually verify the visibility rules work correctly?
