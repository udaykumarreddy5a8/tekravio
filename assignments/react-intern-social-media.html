// The Problem
ConnectHub is the most interaction-heavy React assignment. Every interaction should feel instant using optimistic updates. The feed uses useInfiniteQuery. Like/unlike uses useMutation with onMutate for optimistic updates. The follow button has 4 distinct states that must be rendered correctly based on the followStatus field returned by the API. No interaction should require waiting for an API response to update the UI.
// 01 · Modules
Five Modules — 100 Marks

This is a frontend assignment. Every module requires working UI components, not just API calls. Show state, loading, and error states for every async operation.

01
Feed & Infinite Scroll
// 22 marks
▼

The home feed with infinite scroll and post interactions.

Infinite scroll feed: Use TanStack Query's useInfiniteQuery to load the home feed. When the user scrolls to within 200px of the bottom, automatically load the next page. Use an IntersectionObserver hook to detect the scroll trigger. Show a loading spinner at the bottom while fetching more.
Post card: Each PostCard: user avatar (with click-to-profile), username, display name, timestamp (relative: '2h ago'), post text (truncated at 3 lines with 'Show more'), image grid (1 image = full width, 2 = side by side, 3+ = grid with overflow count). Like button, comment count button, share button.
Optimistic like: Clicking the like button: immediately toggle the icon filled/unfilled and increment/decrement the like count. Call the like/unlike API in the background. If the API fails, revert to original state and show an error toast. The UI must never wait for the API response to update the like icon.
Empty feed: When the user follows no one, show an empty state with suggestions: 'Start by following some people' with a list of recommended accounts (fetched from a public API endpoint).
02
Post Creation & Comments
// 22 marks
▼

Creating posts and the comment thread.

Post composer: A 'What's on your mind?' input at the top of the feed. Clicking expands to a modal with: textarea (character countdown 2000), image URL input (+ Add Image button with preview), visibility selector (PUBLIC / FOLLOWERS_ONLY / PRIVATE) as icon buttons. 'Post' button disabled if text is empty.
Comment section: Clicking the comment count button on a post expands a comment panel below the post card (not a separate page). Shows top-level comments with their direct replies collapsed under a 'N replies' toggle. Reply form shows inline when clicking 'Reply' on a comment.
Nested comments: Replies are indented. A 'View N replies' expander shows them. The reply input auto-fills @username. Character limit 500 with live countdown. Submitting a reply optimistically adds it to the thread.
Delete post/comment: Author can delete their own posts and comments. A '...' menu on hover shows 'Delete'. Confirmation popover (not modal). After deletion, the post/comment fades out with an animation and is removed from the DOM.
03
Follow System & Profile
// 20 marks
▼

User profiles, follow/unfollow, and the private account experience.

User profile page: Header: cover photo area, avatar (large), display name, username, bio, follower/following counts (clickable to open lists). A 'Follow' / 'Following' / 'Requested' button based on relationship state. Post grid below.
Follow button states: Four states with distinct visual treatment: (1) Follow (outlined button), (2) Following (filled green, hover shows 'Unfollow' in red), (3) Requested (grey, hover shows 'Cancel Request'), (4) Blocked (shown as 'Blocked', with an option to unblock). All transitions optimistic.
Private account: If viewing a private account you don't follow: show avatar + bio + follower count, but replace the post grid with a lock icon + 'This account is private. Follow to see their posts.' If you sent a follow request, show 'Requested — waiting for approval.'
Followers/following lists: Modal showing the list. Each entry: avatar, name, username, follow button (same 4-state button). The list is infinite-scroll within the modal. Search input filters the list client-side.
04
Notifications
// 18 marks
▼

Real-time-feeling notification bell and notification list.

Notification bell: Header icon with unread count badge. The badge shows up to 99+. Clicking opens a dropdown of recent notifications (last 5). A 'View all' link goes to the notifications page. The unread count refreshes every 30 seconds via TanStack Query polling.
Notification types: Each notification has a specific icon and message: 🔔 'Alice followed you', 💙 'Bob liked your post', 💬 'Carol commented on your photo', ✅ 'Dave approved your follow request'. Clicking a notification navigates to the relevant content and marks it as read.
Notifications page: Full list of notifications, paginated. Unread items have a blue left border. 'Mark all as read' button at the top. Each item shows: avatar, message, time, and is clickable to the relevant content.
Polling vs real-time: Implement polling (every 30 seconds via TanStack Query refetchInterval). In your README, explain what you would replace polling with in a production app (WebSocket or SSE) and why.
05
Search & Explore
// 18 marks
▼

User search and content discovery.

Search page: A search input with debounce (300ms). Results split into two tabs: People and Posts. People results show the 4-state follow button. Post results show a mini card (author, truncated text, like count).
Trending hashtags: A sidebar widget on the feed page showing top 10 hashtags (fetched from GET /api/hashtags/trending). Clicking a hashtag navigates to its posts page. The widget refreshes every 5 minutes.
Hashtag page: /hashtag/{tag} — a feed of posts with that hashtag using the same infinite-scroll PostCard. A header shows the hashtag, total post count.
Suggested accounts: A sidebar widget on the feed showing 5 accounts to follow (random or by follow-of-follow logic). Each has the follow button. 'Refresh' link loads a new set of 5.
// 02 · Design Questions
Answer in README.md

These come up in every React frontend interview.

Q1
Your optimistic like updates the local like count instantly. But TanStack Query's cache has the old count. When the post card re-renders from the cache (e.g., after a page focus), it might show the old count momentarily. How do you keep the optimistic update in sync with the cache?
Q2
The notification badge shows unread count from a query that polls every 30 seconds. The user reads a notification on the notifications page, marking it as read. But the bell badge still shows the old unread count until the next 30-second poll. How do you make the badge update immediately after the read action?
Q3
The feed uses infinite scroll. The user scrolls down 10 pages, clicks a post to view it, then presses Back. Where do they land in the feed? How do you restore the user's scroll position in the infinite list? What does TanStack Query do by default, and is it correct?
Q4
The follow button has 4 states that depend on an API response. While the API is loading (e.g., after clicking Follow), what state does the button show? If you show a spinner, what prevents the user from clicking it again during the loading?
