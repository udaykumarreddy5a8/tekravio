Build the React frontend for ShopNest e-commerce. The core UI challenges: a product listing with a sticky filter sidebar, a cart drawer that slides in from the right with live stock warnings, a multi-step checkout, and an order history with status tracking. // The Problem
ShopNest frontend is performance-sensitive — product images must lazy-load, the filter sidebar must not re-render the entire grid on every keystroke. The cart state lives in Zustand so it persists across page navigation. However, cart quantities must be validated against actual stock from the API before checkout. Use URL search params for filters so the browsing state is shareable and bookmarkable.
// 01 · Modules
Five Modules — 100 Marks

This is a frontend assignment. Every module requires working UI components, not just API calls. Show state, loading, and error states for every async operation.

01
Product Catalogue & Variant Selection
// 22 marks
▼

Product browsing with a filter sidebar and variant-aware product detail.

Product grid: Responsive grid (2 cols mobile, 3 tablet, 4 desktop). Each ProductCard: image with lazy-load (loading='lazy'), product name, brand, price range, average rating (stars), stock status badge (IN_STOCK / LOW_STOCK / OUT_OF_STOCK). OUT_OF_STOCK cards show a greyed overlay.
Filter sidebar: Sticky sidebar (desktop) / bottom sheet (mobile). Filters: category (accordion), brand (checkboxes, searchable), price range (dual-handle slider), rating (minimum stars), in-stock only toggle. Active filter count badge on the mobile filter button. Clear all filters button.
URL-based filters: All filter state lives in URL search params. Copy-paste the URL to get the same filtered view. Navigating back resets to the previous filter state via browser history.
Product detail: Product name, all images (thumbnail row + main image), price, brand, description. Variant selector: Size as a button grid, Colour as a swatch grid. Selected variant shows its specific price and stock status. Disabled button for out-of-stock variants. 'Add to Cart' button is disabled if no variant selected.
02
Shopping Cart
// 22 marks
▼

A slide-in cart drawer with live stock validation.

Cart drawer: Slides in from the right when cart icon is clicked. Shows all items with: product image, name, variant name, unit price, quantity stepper (+ / -), line total, remove button. Cart icon in header shows item count badge with a pop animation when item is added.
Quantity stepper: The + button is disabled when quantity equals available stock. A tooltip shows 'Only N left'. Decreasing to 0 shows a trash icon that removes the item. Changing quantity calls the update API and shows an inline loader on the stepper.
Stock warning: If a cart item's available stock has dropped below the cart quantity since it was added, show an inline warning badge: '⚠ Only 2 left, you have 3'. The 'Proceed to Checkout' button is disabled until all items are within available stock.
Coupon input: A coupon code input at the bottom of the cart. On apply, show loading state, then either show the discount amount in green or an error in red. Display applied coupon with a ✕ remove button.
03
Checkout Flow
// 20 marks
▼

A three-step checkout: address, review, confirm.

Step 1 — Address: List of saved addresses as selectable cards. 'Add new address' expands an inline form. Selected address highlighted. If no saved addresses, the form shows automatically.
Step 2 — Review order: Final order summary: items, coupon discount, total. An editable quantity field per item (calls the cart update API). A warning if any item went out of stock while on this page (real-time check via a useQuery with short staleTime).
Step 3 — Place order: A single prominent 'Place Order' button with the total amount. On click: disable button, show spinner, call order placement API. On success: navigate to order success page with order ID. On 'out of stock' error: navigate back to step 2 with the problematic item highlighted in red.
Checkout stepper: A visual stepper at the top showing current step. Clicking a completed step navigates back to it (only backward navigation in the stepper, not forward skip).
04
Orders & Wishlist
// 18 marks
▼

Order history with live status and a persistent wishlist.

Order history: List of orders with: order number, date, item count, total, status badge with colour coding. Clicking opens order detail showing all items with their snapshots (name, variant at time of order, price paid). A timeline at the bottom shows status progression (PENDING → CONFIRMED → SHIPPED → DELIVERED).
Order cancellation: For PENDING orders: a 'Cancel Order' button in the detail view. Clicking shows a confirmation modal: 'Are you sure? Stock will be restored and your payment refunded.' After cancellation, the order status badge updates without a full page reload.
Wishlist: A heart icon on each product card. Filled heart = wishlisted, empty = not. Clicking toggles with an optimistic update. The Wishlist page shows all wishlisted products with their current stock status and price. A product that came back in stock (any variant) shows a 'Back in Stock!' badge.
Review form: After an order is DELIVERED, 'Write a Review' button appears on the order item. A star-rating component (clickable stars) + textarea. Submit adds the review to the product.
05
Admin Product Management
// 18 marks
▼

An admin panel for managing products and inventory.

Product management table: ADMIN-only route. Table of all products: image thumbnail, name, category, variants count, total stock, status (active/inactive) toggle. Inline status toggle calls the API and updates the row.
Create / Edit product: A full-page form with: basic info fields, a dynamic variant builder (add row / delete row: name, SKU, additionalPrice, initialStock), image URL inputs (add/remove fields). Form uses React Hook Form with a FieldArray for variants. Client-side validation before submit.
Inventory update modal: Stock adjustment modal: choose variant from dropdown, choose ADD / REMOVE / SET, enter quantity, enter reason. Shows current stock prominently. After update, the product table row refreshes.
Low stock alert panel: A sidebar widget showing variants with stock ≤ 5. Clicking a variant item opens the inventory update modal pre-filled with that variant.
// 02 · Design Questions
Answer in README.md

These come up in every React frontend interview.

Q1
The product filters are stored in URL params. A user applies 3 filters, then adds an item to the cart (which lives in Zustand). They press the browser back button. The URL changes (filter removed), but does the cart change? Should it? What does your implementation do?
Q2
The checkout step 2 checks if items are still in stock using useQuery. If the user leaves the tab open for 30 minutes, the query is stale. How do you ensure they always see current stock when they resume the checkout?
Q3
The cart drawer shows a quantity stepper. The maximum quantity is set to the available stock returned from the last API call. But what if stock changes between the cart page load and the checkout submission? Where does the real stock enforcement happen?
Q4
You use Zustand for cart state (in memory). The user adds 3 items to their cart, then closes the browser. When they reopen, the cart is empty. How would you persist the cart across browser sessions? What are the trade-offs?
