// The Problem
FinSmart frontend is chart-heavy and number-heavy. Use Recharts for all visualisations. All monetary values must use the Indian number format (₹1,23,456.78) — use Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' }). Every form must prevent double-submission (disable button on submit). Every API error must be caught and shown to the user — no silent failures.
// 01 · Modules
Five Modules — 100 Marks

This is a frontend assignment. Every module requires working UI components, not just API calls. Show state, loading, and error states for every async operation.

01
Dashboard Overview & Charts
// 22 marks
▼

The main dashboard: stat cards, income/expense chart, category breakdown pie chart.

Stats row: Four animated stat cards: Total Income, Total Expenses, Net Savings, Savings Rate (%). Cards show current month data. Each has a colored indicator showing MoM change (green arrow up / red arrow down with percentage).
Income vs Expense chart: A Recharts BarChart showing the last 6 months side-by-side bars (income blue, expense red). Use ResponsiveContainer to make it fill its parent. Hovering a bar shows a custom tooltip with exact amounts. Month selector to shift the window.
Category donut chart: A PieChart (donut style) showing expense breakdown by category for the selected month. Clicking a slice filters the transaction table below to show only that category's transactions. Selected slice animates outward.
Account balances: A horizontal list of account cards. Each shows: account name, type icon, current balance (formatted as ₹X,XX,XXX.XX), and a mini sparkline chart of the last 7 days' balance (use Recharts LineChart at small size).
02
Transaction Table & Entry Form
// 22 marks
▼

The core workflow: logging transactions quickly and finding them easily.

Transaction table: Paginated table (20 rows/page) with columns: date, account, category icon + name, description, amount (income green, expense red). Column header click sorts. Multi-filter bar above: date range picker, account dropdown, category multi-select, type toggle (All/Income/Expense). Filters are applied via API query params (not client-side filtering of all data).
Quick-entry form: A persistent form panel (sidebar or bottom drawer). Fields: amount, type (toggle button, not dropdown), category (icon grid picker, not dropdown — faster to click), account (dropdown), date (default today), description. Submit with Enter key. After submit, the transaction table updates instantly via React Query cache invalidation and the form resets, ready for next entry.
Inline edit: Clicking a transaction row enters inline edit mode for the description and amount fields. Press Enter to save, Escape to cancel. Show save/cancel buttons. Unsaved changes show a dirty indicator (dot on the row).
Bulk delete: Checkboxes on each row. 'Select All' checkbox in header. Bulk delete button appears when ≥ 1 selected, showing count: 'Delete 3 transactions'. Confirmation modal before proceeding.
03
Budget Tracker
// 20 marks
▼

Monthly budgets visualised as progress bars with status colours.

Budget list: A card grid, one per budget category. Each card: category icon + name, budget amount, spent amount, remaining, percentage used as a progress bar. Bar colour: green (<70%), amber (70–90%), red (>90%). Cards sorted: over-budget first.
Budget form: Click '+' to add a budget. Inline form (no modal): category selector (grid of icons), amount input. Validation: cannot set budget for a category that already has one for the current month. On submit, optimistically add to the list.
Month switcher: Navigation arrows to switch months. Budget data reloads for the selected month. A 'This Month' button returns to current.
Overspend warning: When any category crosses 100% of budget, show a prominent banner at the top of the page: 'You have overspent in 2 categories this month.' Clicking it scrolls to those cards.
04
Savings Goals
// 18 marks
▼

Goal progress cards with deposit flow.

Goal cards: Each goal shows: name, target amount, current amount, progress bar, days remaining, projected completion date. A visual ring chart (not just a bar) showing percentage complete. Achieved goals show a completion confetti animation (use canvas-confetti).
Deposit modal: Clicking 'Add Deposit' opens a modal: amount input, account selector (to deduct from), note. After submit, update the goal's current amount optimistically and reload the goal card.
Create goal: A form: name, target amount (with suggested presets: Emergency Fund 3 months, Vacation, etc.), target date, linked account. The form validates that target date is in the future.
Goals summary: At top of the Goals page: 'Total Saved: ₹X across Y goals'. A simple progress toward collective savings target.
05
Reports & Export
// 18 marks
▼

The analytics view that turns transactions into insights.

Monthly report: Two-column layout: left shows the summary numbers (total income, expenses, net savings, top 3 categories with bars), right shows the income vs expense bar chart. A month/year picker at the top. Print button that opens the browser print dialog with a print-friendly CSS.
Category drill-down: Clicking a category in the report shows a transaction list for that category + month in a slide-in panel. The list is paginated.
CSV export: 'Export CSV' button downloads a CSV of all transactions in the filtered date range. Use a client-side CSV generator (no backend endpoint needed). Use the Blob API and a hidden anchor click. Filename: finsmart-transactions-2026-06.csv.
Type safety for money: Create a Money type and a formatMoney(amount: number, currency: string) utility. Use Indian number formatting: ₹1,23,456.78 (not ₹123,456.78). Every number in the UI that represents money must pass through this formatter.
// 02 · Design Questions
Answer in README.md

These come up in every React frontend interview.

Q1
Your transaction table fetches page 1. The user adds a transaction. You invalidate the query cache. But the new transaction might appear on page 1 (pushing another item to page 2) or might not appear on page 1 at all depending on sort order. How do you handle this UI inconsistency?
Q2
The category donut chart slice click should filter the transaction table. The chart and table are separate components. How do you share this 'selected category' state? Local state in the parent? Zustand? URL params? What are the trade-offs of each approach?
Q3
A user enters 20 transactions in a row using the quick-entry form. Each submit triggers a React Query mutation that invalidates the transaction table cache. The table refetches 20 times. Is this a performance problem? How would you batch or debounce cache invalidations?
Q4
You need to display ₹1,23,456.78 (Indian format) not ₹123,456.78. The built-in Intl.NumberFormat supports Indian locale. Write the exact formatter call and explain why using en-IN locale matters.
