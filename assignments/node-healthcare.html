// Project Context
Note: You are not expected to deploy to AWS ECS/EKS or build microservices for this assignment. Focus on getting the core Node.js backend, S3 integration, Textract, and FCM working cleanly. Architecture decisions matter more than completeness at every edge case.

Patients or admins upload prescription images, stored in AWS S3 and processed using AWS Textract to extract medicine details, dosage, and timings. The backend schedules reminders and sends push notifications through Firebase Cloud Messaging (FCM) and optionally WhatsApp reminders. The platform supports recurring medicine alerts, diet reminders, prescription management, and patient tracking.

Built using Node.js (Express), PostgreSQL, Sequelize, AWS services, and a React or Flutter frontend, with a scalable architecture that can later evolve into a microservices-based healthcare platform.

// Core Tasks

What You Must Build

01
Auth, Patient & Admin Management
// 15 marks · JWT + Role basics

Set up the security and user management layer. Every API must be secured. Role-based access must be enforced from the start — this is a healthcare app.

JWT authentication — register, login, refresh token, logout (token blacklist using Redis or in-memory Set)
Roles: ADMIN and PATIENT — different route access enforced via middleware, not controller conditionals
Patient profile API — CRUD: name, age, medical history, FCM device token, WhatsApp number. Validate all inputs with Joi or express-validator
Admin APIs — list all patients, activate/deactivate, view any patient's prescriptions
Passwords — hashed with bcrypt. Never stored or returned in plaintext
authMiddleware.jsJS
const authMiddleware = async (req, res, next) => {
  const token = req.headers['authorization']?.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'No token' });
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch { res.status(401).json({ error: 'Invalid token' }); }
};

const requireRole = (role) => (req, res, next) => {
  if (req.user.role !== role)
    return res.status(403).json({ error: 'Forbidden' });
  next();
};
02
Prescription Upload — S3 + AWS Textract
// 20 marks · AWS S3 + Textract integration

Patients upload a prescription image. Your backend stores it in S3, sends it to Textract, parses the extracted text into structured medicine data, and saves it to PostgreSQL. Handle failures gracefully.

Multer + S3 — use multer-s3 or pipe the buffer to S3 directly. Store with key: prescriptions/{patientId}/{uuid}.jpg. Validate file type (JPG/PNG/PDF) and size ≤ 10MB
AWS Textract — call DetectDocumentText using @aws-sdk/client-textract. Parse LINE blocks to extract medicine name, dosage, frequency, duration
Prescription model — store: S3 URL, raw Textract response (JSONB), extracted medicines array, upload timestamp, status (PENDING / DONE / FAILED)
Fallback — if Textract extraction fails or confidence is low, return a clear error and allow manual medicine entry as fallback
Prescription history API — paginated list for a patient, filter by date range, most recent first
// AWS SDK v3

Use @aws-sdk/client-s3 and @aws-sdk/client-textract (modular SDK). Do not use the old aws-sdk v2 — it's deprecated. Use environment variables for credentials. Never hardcode AWS keys.

03
Medicine Schedule & Reminder Engine
// 20 marks · Core feature

Build the scheduling engine using node-cron. It must reliably poll for due reminders and fire FCM notifications. Handle edge cases like missed reminders on server restart.

Medicine schedule model — medicine name, dosage, frequency (ONCE_DAILY / TWICE_DAILY / THRICE_DAILY / CUSTOM), time slots as array, start date, end date, is_active
node-cron scheduler — run every 5 minutes, query for reminders due in the next 5-minute window, fire FCM for each, log result to reminder_log table
Recurring support — daily, weekly, custom interval in hours
Snooze API — patient snoozes by 10/20/30 minutes, system updates next_reminder_at timestamp
Taken / Skipped API — patient marks reminder taken or skipped, logged in reminder_log with timestamp
Adherence calculation — percentage of reminders marked taken vs total for the last 7 days
04
Push Notifications — Firebase FCM
// 15 marks · Notification layer

Integrate Firebase Admin SDK to deliver push notifications. Notifications must be structured, actionable, and logged. Invalid tokens must be handled cleanly.

Firebase Admin SDK — initialise with service account JSON from environment variable. Send FCM message with title, body, and data payload
Notification payload — include scheduleId, action (TAKE / SNOOZE / SKIP), patientId in FCM data map so the app can handle deep-linking
notification_log table — every FCM call logged: patientId, scheduleId, sent_at, fcm_response, status (SUCCESS / FAILED)
Retry on failure — if FCM call fails, retry once after 60 seconds. Log final status regardless
WhatsApp fallback (optional) — if patient has no FCM token, send message via Twilio WhatsApp API or WATI
notificationService.jsJS
const sendReminder = async (patient, schedule) => {
  const message = {
    token: patient.fcm_token,
    notification: {
      title: `Time for ${schedule.medicine_name}`,
      body:  `${schedule.dosage} · Tap to confirm`
    },
    data: {
      scheduleId: String(schedule.id),
      patientId:  String(patient.id),
      action:     'TAKE'
    }
  };
  const response = await admin.messaging().send(message);
  return response; // FCM message ID
};
05
Diet Reminder Module
// 15 marks · Secondary feature

Extend the system to support diet and meal reminders alongside medicine reminders. Use the same cron-based scheduler — just a different entity type and notification template.

DietPlan model — meal type (BREAKFAST / LUNCH / DINNER / SNACK), description, scheduled_time, dietary_restrictions, assigned patient, start/end date
Admin creates diet plan — assign to a patient, set start/end dates
Patient views diet plan — paginated list, today's meals highlighted in response
Diet reminders — node-cron scheduler sends FCM reminders 15 minutes before meal time
Diet adherence tracking — mark meals as eaten/skipped, calculate weekly compliance percentage
