// The Problem
EduTrack is an online learning platform. It has two user roles: STUDENT and INSTRUCTOR. Instructors create courses with multiple modules, each containing lessons. Students enroll in courses and track their progress lesson by lesson. A course also has quizzes — multiple-choice questions with a passing score threshold.

Your job is to build the REST API backend. Do not just build CRUD. Think about the real rules: a student cannot mark a lesson complete unless they are enrolled in that course; a student cannot retake a passed quiz; a student becomes eligible for a certificate only when all lessons in a course are marked complete and all required quizzes are passed.

Five Modules — 100 Marks

01
Course & Content Management
// 20 marks
▼

Instructors manage courses, modules, and lessons. This is the content layer — everything else depends on it.

Course.java (entity snippet)JPA
@Entity
@Table(name = "courses")
@Getter @Setter @Builder
public class Course {
    @Id @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;

    @NotBlank @Size(min=5, max=100)
    private String title;

    @Enumerated(EnumType.STRING)
    private Category category;

    @OneToMany(mappedBy="course", cascade=CascadeType.ALL, orphanRemoval=true)
    @OrderBy("moduleOrder ASC")
    private List<CourseModule> modules = new ArrayList<>();
    // ... remaining fields
}
Course entity: Fields: title, description, thumbnailUrl, category (enum: PROGRAMMING, DESIGN, DATA_SCIENCE, BUSINESS, OTHER), difficulty (BEGINNER, INTERMEDIATE, ADVANCED), price (BigDecimal, 0 means free), published (boolean), createdBy (Instructor). A course has many CourseModules, ordered by moduleOrder.
Lesson entity: A CourseModule has many Lessons. Fields: title, contentUrl (video/PDF URL), durationMinutes, lessonOrder, type (VIDEO, ARTICLE, QUIZ). Lessons cannot be deleted if any student has marked progress on them — throw a custom LessonInUseException.
APIs: POST /api/courses — create (INSTRUCTOR only). PUT /api/courses/{id}/publish — publish a course (validates at least 1 module with 1 lesson exists). GET /api/courses/{id} — full course with modules and lessons. DELETE /api/courses/{id} — only if zero enrollments, else throw CourseHasEnrollmentsException.
Validation: Course title: 5–100 chars. Price: 0 to 99999.99. A module must have at least 1 lesson before the course can be published. Validate all of this at the service layer, not just controller.
02
Enrollment & Progress Tracking
// 22 marks
▼

Students enroll in courses and track progress lesson by lesson. The real logic is in calculating progress percentage and determining completion.

Enrollment: POST /api/enrollments — enroll the authenticated STUDENT in a course. Prevent duplicate enrollment (throw AlreadyEnrolledException). A student cannot enroll in an unpublished course.
Lesson progress: POST /api/progress/lessons/{lessonId}/complete — mark a lesson as complete. Validate: the student must be enrolled in the course this lesson belongs to. If already marked complete, return current state (idempotent). Store: studentId, lessonId, completedAt.
Progress calculation: GET /api/enrollments/{enrollmentId}/progress — return: total lessons in course, completed lessons count, percentage (0–100), list of incomplete lesson IDs. Calculate in service layer, not in DB query. Cache the percentage? Not required, but note where you would.
Course completion: A student is “course-complete” when: (a) all lessons marked complete AND (b) all required quizzes passed. Expose GET /api/enrollments/{id}/completion-status returning a JSON object with lessonsComplete, quizzesPassed, eligible (boolean), and certificateCode (UUID, generated once eligible, null otherwise).
// Note

Store completedAt timestamp on LessonProgress. This allows you to calculate 'last active date' for a student — useful for the dashboard.

03
Quiz & Assessment System
// 22 marks
▼

Courses have quizzes with multiple-choice questions. Quizzes have a pass threshold. Students get immediate results and limited retakes.

QuizAttemptService.java (scoring logic)Service
public AttemptResult submitAttempt(UUID quizId, List<AnswerDto> answers) {
    Quiz quiz = quizRepository.findById(quizId)
        .orElseThrow(() -> new ResourceNotFoundException("Quiz not found"));
    validateAttemptEligibility(quiz, currentUser());

    long correct = answers.stream()
        .filter(a -> isCorrectOption(a.questionId(), a.selectedOptionId()))
        .count();
    double score = (correct * 100.0) / quiz.getQuestions().size();
    AttemptStatus status = score >= quiz.getPassPercentage()
        ? AttemptStatus.PASSED : AttemptStatus.FAILED;

    // save attempt, update enrollment if all quizzes passed
    return saveAttemptAndReturn(quiz, score, status, answers);
}
Quiz entity: Quiz belongs to a CourseModule (like a lesson). Fields: title, passPercentage (default 70), maxAttempts (default 3), timeoutMinutes. Quiz has many Questions; each Question has many Options (one marked correct). Do not expose which option is correct in the student-facing GET APIs.
Submit quiz attempt: POST /api/quizzes/{quizId}/attempts — body: list of {questionId, selectedOptionId}. Validate: enrolled, not exceeded maxAttempts, no in-progress attempt. Calculate score in service: (correct answers / total questions) * 100. Set status to PASSED or FAILED. Return score and pass/fail.
Attempt rules: A student who has PASSED cannot retake. A student who has FAILED and not reached maxAttempts can retry. Return QuizAlreadyPassedException if passed. Return MaxAttemptsExceededException if out of retakes.
Attempt history: GET /api/quizzes/{quizId}/my-attempts — return all attempts for the authenticated student: attempt number, score, status, submittedAt. Sort newest first.
04
Search, Filter & Student Dashboard
// 18 marks
▼

Search courses and build the student's personal dashboard. Intermediate pagination required.

Course search: GET /api/courses?search=java&category=PROGRAMMING&difficulty=INTERMEDIATE&free=true&page=0&size=10. Use Spring Data's Specification or a JPQL query with optional filters. Return paginated results with: title, instructor name, price, enrolled student count, average rating (placeholder for now), difficulty, category.
Student dashboard: GET /api/students/me/dashboard — return: (a) active enrollments with progress %, last activity date; (b) completed courses with certificate code; (c) upcoming quiz deadlines (quizzes in enrolled courses not yet attempted). No pagination needed here — return all.
Instructor dashboard: GET /api/instructors/me/dashboard — return: (a) total published courses, (b) total students enrolled across all courses, (c) per-course stats: enrollment count, average quiz score, completion rate %. Compute completion rate as: students with all lessons done / total enrolled.
Popular courses: GET /api/courses/popular?limit=5 — top 5 courses by enrollment count. Simple query, no ML needed. Return as a list, not paginated.
05
Testing & Exception Handling
// 18 marks
▼

Clean APIs require clean error responses and reliable tests. This module is often rushed — don't rush it.

Global exception handler: Create a @RestControllerAdvice that handles: ResourceNotFoundException (404), AlreadyEnrolledException (409), QuizAlreadyPassedException (409), MaxAttemptsExceededException (422), LessonInUseException (409), MethodArgumentNotValidException (400 with field errors). All responses follow: {status, message, timestamp, errors[]}.
Unit tests: Write JUnit 5 + Mockito unit tests for QuizAttemptService covering: (a) successful pass, (b) successful fail, (c) attempt when already passed throws exception, (d) attempt when max retries exceeded throws exception, (e) score calculation with all wrong answers, (f) score calculation with all correct answers. 6 test cases minimum.
Integration test: Write one @SpringBootTest integration test for the enrollment flow: create course → publish → enroll student → complete all lessons → verify completion status returns eligible=true.
OpenAPI: All endpoints documented in Swagger. Every request/response DTO annotated with @Schema descriptions. Authentication requirement shown. Access at /swagger-ui.html after docker-compose up.
// Note

For JWT auth, keep it simple: @PreAuthorize('hasRole("STUDENT")') on endpoints. You do not need to implement registration/login from scratch — provide a test token generator endpoint POST /api/test/token?role=STUDENT for reviewers to use.

// 02 · Design Questions
Answer These in README.md

Short answers. We ask follow-ups in the review call.

Q1
A student completes all lessons in a course but fails the quiz 3 times (max attempts). They are now stuck — cannot get the certificate but cannot retake the quiz. How should your system handle this? Should an instructor be able to reset attempts?
Q2
You mark a lesson complete with a POST request. If the same request is sent twice, what happens in your implementation? Is your endpoint idempotent? What HTTP status do you return on the second call?
Q3
The quiz question entity has an 'isCorrect' field on options. What happens if an instructor accidentally marks two options as correct for the same question? Where do you validate this, and what error do you return?
Q4
A student is enrolled in 10 courses. The dashboard API calculates progress for all 10 in a single request. What is the N+1 query problem, and how does your implementation avoid it?
