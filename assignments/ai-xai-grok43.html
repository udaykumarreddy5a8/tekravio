// The Context
Grok 4.3 is xAI's most capable and fastest model, released April 30, 2026. It supersedes the Grok 4.20 beta line and is built on xAI's Colossus supercomputer — approximately 200,000 GPUs running at 10× the compute used to train Grok 3. The model supports text, image, voice, and video natively, giving it a multimodal breadth that GPT-5.5 lacks (no native video).

Grok 4.3's defining differentiator: native X/Twitter data access via server-side tools. No other frontier model has real-time access to the X/Twitter firehose. At $1.25/$2.50 per million tokens, it is also one of the most competitively priced frontier models. Server-side tools include web search, X search, code execution, files, and remote MCP.
// 01 · Research Modules
Five Research Modules — 100 Marks

Each module graded on accuracy, sourcing, and applied thinking. Primary sources only.

01
Colossus Supercomputer & What 10× Compute Actually Delivers
// 20 marks
▼

Grok 4 was trained on Colossus with ~200,000 GPUs at 10× the compute of Grok 3. Document what this scale means for capability, not just as a marketing claim.

Colossus cluster specification: Research what is publicly known about xAI's Colossus supercomputer: GPU architecture, total FLOP capacity, and data centre location. How does ~200,000 GPUs compare to the known training infrastructure of OpenAI, Google, and Anthropic? What does training at this scale typically unlock in terms of emergent capabilities?
10× compute and scaling laws: Apply the Chinchilla scaling laws to estimate what a 10× compute increase should yield in terms of benchmark improvement. Does Grok 4.3's actual benchmark performance match, exceed, or fall short of the theoretical prediction? Where does it overdeliver and where does it underdeliver?
Grok 4 vs Grok 4 Heavy vs Grok 4.3: Grok 4.3 supersedes the Grok 4.20 beta line. What changed between Grok 4.20 and 4.3? What is Grok 4 Heavy and who is it designed for? When would you choose Grok 4 Heavy over Grok 4.3?
Video processing: Grok 4.3 supports native video processing, unlike GPT-5.5. Document the video input limits, supported formats, and what the model can reliably do with video content. Provide one specific enterprise use case where video support creates value that GPT-5.5 cannot deliver.
Context window discrepancy: Grok 4.3 has a 1M token API context window but a 2M token context in the X/Grok consumer app. Why the discrepancy? What technical or business reason explains this? For a developer building on the API, when does 1M tokens become a limiting constraint?
02
X/Twitter Integration & Real-Time Data Access
// 20 marks
▼

Grok 4.3 has a capability no other frontier model has: native access to live X/Twitter data. Document what this means in practice.

Server-side tools complete list: Grok 4.3 supports five server-side tools: web search, X search, code execution, files, and remote MCP. For each tool: document what data or service it accesses, how it is invoked in an API request, any known rate limits, and one specific use case where this tool creates value that other models cannot easily replicate.
X search vs web search: What does access to the X/Twitter firehose enable that general web search cannot? Document specific use cases: real-time market sentiment analysis, breaking news verification, brand monitoring, early financial signal detection. For each, explain why X-specific data has higher value than indexed web data for this task.
Comparison to other models' web access: GPT-5.5 has web browsing. Claude Fable 5 has web search as a tool. Gemini 3.1 Pro has Google Search integration. Grok 4.3 has X search. Document the meaningful differences between these four approaches: what data each can access, latency, and the enterprise use cases each is best for.
Limitations of X data: Be honest: X/Twitter data has real limitations. Document misinformation propagation, bot account contamination, survivorship bias, and recency weighting issues. How should a developer building a production application on Grok's X search account for these limitations in their design?
Remote MCP support: Grok 4.3 supports remote MCP (Model Context Protocol) as a server-side tool — connecting to any MCP-compatible external service without client-side SDK changes. What does this enable for enterprise integrations? Compare to Claude's MCP implementation from the client side.

Benchmarks, Coding & Agentic Performance
// 20 marks
▼

Document Grok 4.3's performance on coding and agentic benchmarks, and the reasoning integration story.

SWE-bench Verified at 80.6%: Grok 4.3 scores 80.6% on SWE-bench Verified. Compare to Claude Fable 5 (95% SWE-bench Verified) and GPT-5.5 (Terminal-Bench 2.0: 82.7%). These are different benchmarks. What does SWE-bench Verified specifically test? What does Terminal-Bench 2.0 test? Why are different benchmarks being used to claim 'best coding model'?
Reasoning + function calling: Grok 4.3 integrates reasoning with function calling and structured outputs. Explain what this means technically: the model can reason about which tools to call and what arguments to pass as part of its thinking process. How does this compare to GPT-5.5's function calling? What is the token cost overhead of enabling reasoning for tool decisions?
Long-chain agentic capability: Grok 4.3 is described as having 'top-tier long-chain agent capabilities.' Design a concrete enterprise workflow that uses all five of Grok's server-side tools together (X search + web search + code execution + files + MCP) in a multi-step agentic task. Which industry and use case benefits most from this full-tool combination?
Prompt caching economics: Grok 4.3 supports prompt caching. For a customer service application using a 50K-token system prompt at 10,000 requests per day at $1.25/M input tokens, calculate the monthly cost without caching vs with caching. What percentage reduction do you achieve?
Grok 4.3 competitive positioning: Build a benchmark table comparing Grok 4.3 to GPT-5.5, Gemini 3.1 Pro, Claude Fable 5, and DeepSeek V4 Pro on: SWE-bench (where available), GPQA Diamond (where available), pricing (input/output), context window, and multimodal support. Which model wins on each axis?
