// Project Context
Note for 2-year experienced candidates: This is your first real enterprise project. Get the core backend working. A subset that works is better than a complete codebase that crashes.

Patients or admins upload prescription images, which are stored in AWS S3 and processed using AWS Textract to extract medicine details, dosage, and timings. The backend system schedules reminders and sends push notifications through Firebase Cloud Messaging (FCM) and optionally WhatsApp reminders. The platform supports recurring medicine alerts, diet reminders, prescription management, and patient tracking.

Built using Spring Boot, PostgreSQL, AWS services, and Flutter, with a scalable architecture that can later evolve into a microservices-based healthcare platform deployed on AWS ECS/EKS.

// Core Tasks

What You Must Build

Six core modules. All required. Partial implementations score partial marks.

01
Auth, Patient & Admin Management
// 15 marks · JWT + Role basics

Set up the security and user management layer. Every API must be secured. Role-based access must be enforced from the start.

JWT authentication — register, login, refresh token, logout with token blacklisting
Roles: ADMIN and PATIENT — different access scopes, enforced at method level with Spring Security
Patient profile API — CRUD: name, age, medical history, FCM device token, WhatsApp number
Admin APIs — view all patients, activate/deactivate patients, view patient prescriptions
Input validation — Bean Validation annotations on all request DTOs, proper error responses

02
Prescription Upload — S3 + AWS Textract
// 20 marks · AWS S3 + Textract integration

The core intelligence of the system. Patients upload a prescription image. Your backend stores it in S3, sends it to Textract, parses the extracted text into structured medicine data, and saves it to the database.

File upload API — accept image (JPG/PNG/PDF), validate size ≤ 10MB and type, upload to S3 with structured key: prescriptions/{patientId}/{uuid}.jpg
AWS Textract integration — call Textract Detect Document Text API, parse response blocks to extract medicine name, dosage, frequency, duration
Prescription entity — store S3 URL, extracted medicine list (even if manually entered as fallback), upload timestamp, status (PENDING / DONE / FAILED)
Error handling — if Textract extraction fails or confidence is low, return a clear error and allow manual medicine entry as fallback
Prescription history API — list all prescriptions for a patient with pagination, filter by date range
03
Medicine Schedule & Reminder Engine
// 20 marks · Core feature

Build the scheduling engine that drives the entire reminder system. This is the heart of the application — it must be reliable, configurable, and handle edge cases correctly.

Medicine schedule model — medicine name, dosage, frequency (ONCE_DAILY / TWICE_DAILY / THRICE_DAILY / CUSTOM), time slots, start date, end date, active flag
Spring Scheduler — poll every 5 minutes for due reminders, fire FCM notifications, log attempt status in reminder_log table
Recurring schedule support — daily, weekly, custom interval in hours
Snooze API — patient can snooze a reminder by 10/20/30 minutes, system reschedules
Taken / Skipped API — patient marks a reminder as taken or skipped, tracked in reminder log table
Adherence calculation — % of reminders marked as taken vs total for the last 7 days
04
Push Notifications — Firebase FCM
// 15 marks · Notification layer

Integrate Firebase Cloud Messaging to deliver real-time push notifications to the Flutter app. Notifications must be structured, actionable, and logged.

FCM service — initialise Firebase Admin SDK, build and send FCM message with title, body, and data payload (medicine name, schedule ID, action buttons)
Notification payload — include scheduleId, action (TAKE / SNOOZE / SKIP), patientId in FCM data map
Notification log table — every FCM call logged: patientId, scheduleId, sent timestamp, FCM response, success/failure
Retry on failure — if FCM call fails, retry once after 60 seconds. Log final status.
WhatsApp fallback (optional) — if patient has no FCM token, send WhatsApp message via Twilio or WATI API
// Important

Use Firebase Admin SDK on the backend — not the client SDK. Server-side FCM messages use a service account JSON. Never hardcode credentials — use environment variables or AWS Secrets Manager.

05
Diet Reminder Module
// 15 marks · Secondary feature

Extend the system to support diet and meal reminders alongside medicine reminders. Diet plans should be separately manageable but integrated into the same notification engine.

Diet plan entity — meal type (BREAKFAST / LUNCH / DINNER / SNACK), description, scheduled time, dietary restrictions, calories (optional)
Admin creates diet plan — assign diet plan to patient, with start/end date
Patient views diet plan — paginated list with today's meals highlighted
Diet reminders — same scheduler handles diet reminders, sent 15 minutes before meal time
Diet adherence tracking — mark meals as eaten/skipped, calculate weekly compliance %
06
Flutter App — Patient Interface
// 15 marks · Frontend (Flutter OR React web)

Build a simple frontend — either a Flutter app OR a React/HTML web interface. It should demonstrate your backend working end-to-end. Functional over polished.

Login screen — calls your Spring Boot auth API, stores JWT in secure storage
Dashboard screen — today's medicine schedule, upcoming reminders, adherence % for last 7 days
Prescription upload — image picker, upload to your backend, view extracted medicines
FCM integration — receive push notifications, tap → navigate to relevant reminder, handle Take/Snooze/Skip actions
Reminder history — list of all past reminders with taken/skipped status and timestamp
