// The Problem
EduTrack frontend connects to the EduTrack Spring Boot/Node/Python API. Mock the API with MSW (Mock Service Worker) during development — your UI should work end-to-end without a running backend. Every component has three states to handle: loading (skeleton/spinner), error (error message + retry), and empty (illustration + helpful message). All three must be implemented for every data-fetching component.

Five Modules — 100 Marks

This is a frontend assignment. Every module requires working UI components, not just API calls. Show state, loading, and error states for every async operation.

01
Course Catalog & Enrollment
// 20 marks
▼

The entry point of the app. Course browsing with real-time filters and smooth enrollment flow.

CourseCard.tsxTSX
interface CourseCardProps {
  course: Course;
  onEnroll: (courseId: string) => Promise<void>;
}

export const CourseCard = ({ course, onEnroll }: CourseCardProps) => {
  const [enrolling, setEnrolling] = useState(false);
  const handleEnroll = async () => {
    setEnrolling(true);
    try { await onEnroll(course.id); }
    catch (e) { toast.error("Enrollment failed"); }
    finally { setEnrolling(false); }
  };
  return ( /* ... card JSX */ );
}
Course listing page: Grid of CourseCard components. Each card shows: thumbnail, title, instructor avatar + name, difficulty badge, category tag, price (or FREE badge), enrolled student count, average rating (stars). Clicking enrolls or navigates to course detail based on enrollment status.
Filter sidebar: Filters: category (multi-select checkboxes), difficulty (radio), price (FREE / PAID / range slider), rating (≥ 4 stars toggle). All filters apply client-side to already-fetched results OR re-query the API on change — document your choice and why.
Search: Debounced search input (300ms) that queries the API. Show a loading skeleton while fetching. Show a 'No results for X' empty state. Preserve search and filter state in URL params so the user can share/bookmark the filtered view.
Enrollment flow: 'Enroll Now' button: (1) show a confirmation modal for paid courses, (2) call the enrollment API, (3) show a loading spinner on the button, (4) on success navigate to the course player, (5) on error show a toast notification. Never leave the button in a broken state.
02
Course Player & Lesson Progress
// 22 marks
▼

The lesson view with a sidebar, video/content area, and real-time progress tracking.

Course player layout: Two-panel layout: left sidebar (module accordion with lesson list), right content area (lesson content). Each lesson in the sidebar shows: title, duration, type icon (video/article/quiz), and a tick if completed. Completed lessons show with a strikethrough + green tick.
Progress bar: A sticky progress bar at the top showing X of Y lessons complete. Updates instantly (optimistically) when user marks a lesson complete. If the API call fails, revert the optimistic update and show an error toast.
Lesson completion: At the bottom of each lesson: 'Mark as Complete' button. Once marked, it changes to 'Completed ✓' (disabled). The button is only available if the user is enrolled. If not enrolled, show 'Enroll to access' overlay instead of content.
Navigation: 'Previous' and 'Next' lesson buttons. Keyboard shortcuts: ArrowRight for next, ArrowLeft for previous. Auto-navigate to next lesson after marking current as complete (after a 2-second delay with a countdown). Remember last-watched lesson in localStorage.
// Note

Use TanStack Query's useMutation with onMutate for optimistic lesson completion. Roll back in onError. This is the pattern that makes the UI feel instant even with slow network.

03
Quiz Interface
// 22 marks
▼

A timed quiz with auto-submit and state persistence across page refreshes.

Quiz UI: Display one question at a time OR all questions on one page (implement one, document your choice). Each question shows MCQ options as clickable cards, not radio inputs. Selected option highlights in the accent color. Questions show a completion indicator (e.g., '3 of 10 answered').
Timer: Countdown timer displayed prominently. When it hits 0, auto-submit whatever answers have been selected. Timer state stored in sessionStorage so a page refresh does not reset it. Show a warning toast when 60 seconds remain.
Submission & result: On submit: show a loading state, then a results screen. Results: score percentage, pass/fail badge, correct vs incorrect per question (reveal correct answer for wrong ones). Show 'Retake Quiz' button if attempts remaining, or 'No retakes remaining' if exhausted.
State persistence: If the user closes the quiz tab and reopens it: restore their in-progress answers and remaining time from sessionStorage. When quiz is submitted or time runs out, clear the stored state.
04
Student Dashboard
// 18 marks
▼

The student's home screen — a clear view of their learning activity.

Enrolled courses: A list (not grid) of enrolled courses with: progress bar (percentage), last activity date, 'Continue' button that navigates to the last incomplete lesson. Sort by last activity, most recent first.
Stats row: Four stat cards: Courses Enrolled, Lessons Completed, Quizzes Passed, Certificates Earned. Animate the numbers counting up on page load (use a simple counter hook: increment from 0 to target over 1 second).
Recent activity: A timeline of the last 10 actions: 'Completed lesson X in Course Y', 'Passed quiz Z', etc. Each item shows a relative timestamp ('2 hours ago'). Implement a custom useRelativeTime(date) hook.
Certificate section: A grid of earned certificates. Each is a styled card with course name, completion date, and a 'Download PDF' button (hits the backend endpoint). Placeholder illustration when no certificates yet.
05
Auth & Protected Routes
// 18 marks
▼

Authentication flow and route protection — the scaffolding for everything else.

Auth pages: Login and Register pages. Forms built with React Hook Form + Zod validation. Show field-level validation errors inline. Show a spinner on the submit button during the API call. On success, store the JWT in memory (not localStorage) and redirect to dashboard.
Token management: Store JWT in memory (Zustand store) and the refresh token in an httpOnly cookie (set by the backend). On page reload, silently refresh the token. Implement a 401 interceptor in Axios that automatically attempts a token refresh on a failed request.
Protected routes: Wrap protected pages in a RequireAuth component. If not authenticated, redirect to login with the intended URL in state so the user is sent back after login.
Loading state: On app startup, while checking auth status (calling /api/users/me), show a full-screen loading spinner. Don't flash the login page before determining auth status — this is a common UX mistake.
// 02 · Design Questions
Answer in README.md

These come up in every React frontend interview.

Q1
You use TanStack Query to fetch course data. A user enrolls in a course. The enrollment success triggers a refetch of the course list. But the user is on page 3 of paginated results. How do you invalidate only the affected query cache entry without refetching all pages?
Q2
The quiz timer is stored in sessionStorage. But what if the user opens the quiz on two tabs simultaneously? Tab 1 is at 4:30 remaining; Tab 2 restores from sessionStorage and also shows 4:30, but they diverge from there. Is this a real problem in your implementation? How would you prevent it?
Q3
Your optimistic lesson completion updates the local progress bar instantly. But if two lessons are marked complete in quick succession (fast clicking), can the progress bar show incorrect values? Walk through the race condition.
Q4
You store the JWT in a Zustand store (memory). The user opens a new tab. The JWT is not in localStorage so the new tab has no token. How does the new tab authenticate? What does the user experience?
